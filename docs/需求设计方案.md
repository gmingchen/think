# 众三思 · 需求设计方案（MVP）

> 本文只讨论「需求」本身：要解决什么问题、给谁用、怎么算做成了、有哪些必须拍板的业务规则。
> 不涉及数据库设计、页面拆分、接口与技术选型。本文同时收录产品定位、三思框架定义与文案规范，为唯一权威需求文档。

---

## 一、需求本质：我们到底在解决什么

两难决策的真实痛点，不是「缺一个建议」，而是三个更底层的东西：

1. **当事人身在局中，视角受限**——只盯着一时的收益或恐惧，看不清风险、退路和长期改变。
2. **冲动窗口**——很多两难（裸辞、大额消费、表白、分手）是在情绪峰值时做的决定，缺一个「强制等一下」的机制。
3. **建议散落在微信聊天记录里**——朋友口头说了两句就过去了，没有结构化、无法沉淀、事后无法复盘「当初谁说了什么、结果如何」。

所以众三思的核心价值不是「帮你做决定」，而是：

> **把一次两难决策，变成一份结构化的、有旁观者参与的、可事后复盘的个人决策档案。**

对应产品三根支柱：**结构化（三思分析框架，落在评议与 AI 参考侧）+ 众议（群内/公开评议）+ 时间（冷静期与复盘）**。

### 1.1 产品定位与三思框架
**产品定位**：人生两难决策评议工具，集众人所见，众三思而后抉择。

沿用古训「三思而后行」，**思危 / 思退 / 思变** 是产品贯穿始终的分析框架。它**不再要求发起人开局就分段填写**——发起人只需在「内容」里自由描述两难处境即可；三思作为**评议人观点、AI 参考**的结构骨架，帮旁观者把分析组织得有条理：
- **思危**：这件事的风险、最坏结果，自己能否承受。
- **思退**：失败之后的退路、止损方案。
- **思变**：做出选择之后生活会带来哪些改变。

### 1.2 与对标产品「钱包请等等」的差异
对标参考「钱包请等等」，差异化在于不做赛博判官审判，改为三思框架 + 多人评议 + 冷静期 + 事后复盘，群内私域为主、公开档配套内容审核：

| 项目 | 钱包请等等 | 众三思 |
| --- | --- | --- |
| 定位 | 消费冲动拦截，赛博判官审批 | 全场景人生抉择，多方审慎权衡 |
| 角色 | 判官（通过 / 驳回） | 评议人（发表观点，选择倾向的备选项） |
| 表单 | 简单填写购物理由 | 发起人自由描述两难（不强制三思分段）；评议/报告按思危·思退·思变结构化 |
| 场景 | 仅限购物消费 | 求职、感情、消费、学业、裸辞、养宠物等全部两难选择 |
| 特色 | 玩梗吐槽为主 | 理性权衡，附带决策复盘功能 |
| 上线策略 | 直接开放公域广场 | MVP 支持「群内 + 公开」两档；群内私域为主，公开档配内容审核 |

## 二、目标用户与关键场景

### 2.1 目标用户
- **发起人**：正面临一个具体的、难以自行拍板的人生两难。情绪上「想听别人的看法，但又怕被别人替自己做决定」。
- **评议人**：发起人所选群组的群成员，或公开广场上的网友，愿意帮忙但又缺乏上下文，需要被引导才能给出有价值的意见。

两类人是同一个人不同时刻的身份，产品必须让「当评议人」这件低成本的事也顺畅，否则发起人发布出去没人评，机制就空转。

### 2.2 典型场景（需求优先级按此排）
| 场景 | 说明 | MVP 是否覆盖 |
| --- | --- | --- |
| 要不要裸辞 / 换 offer | 高风险、长冷静期、需要旁观者补盲 | ✅ 核心 |
| 要不要买大额消费品（相机、车） | 冲动型，冷静期价值最大 | ✅ 核心（对标差异场景） |
| 感情抉择（表白 / 复合 / 异地） | 强隐私，只信自己人 | ✅ 核心（群内私密可见正好匹配） |
| 学业 / 考研 / 留学 | 多方权衡 | ✅ 核心 |
| 养宠物 / 搬家 / 借钱给人 | 长尾两难 | ✅ 通用表单可承载 |

## 三、核心业务规则（已定稿）

> 这几条是需求能否成立的关键。以下均为确定的落地规则，不再保留待定项。

### 3.1 评议的登录、身份与可见范围
MVP 不建独立账号体系、不做通讯录同步；身份一律以微信 `openid` 记录。群组仅维护「群—成员」的 `openid` 关系，不引入独立注册。确定规则如下：

- **浏览与登录**：进入小程序即**静默登录**（`wx.login` 换取 `openid`，用户无感、无授权弹窗），以 `openid` 作为唯一身份并自动建档（「加入时间」= 首次登录建档时间，见 §4.4）。能否进入浏览由可见范围决定（见下）——公开档任何人可浏览，群内档仅群成员可浏览（非成员即使拿到链接也不可见）；**昵称/头像**不依赖授权弹窗，在需要时引导用户主动填写（微信头像昵称填写能力，见 §4.4）。登录身份用途：区分「谁评的」（支撑 §3.5 复盘对照），以及校验群成员资格。
- **登录失败降级**：静默登录失败（如网络异常）时，**仍可浏览**公开档决策单（群内档需身份校验不可达），可重试登录；**发布与评议前必须已登录**（持有 `openid`）且已填写昵称/头像，页面保留引导提示，不出现白屏 / 报错。
- **发起人不可评议自己的决策单**：发起人对自己的两难已在局中，其自评无旁观补盲价值，故本人对自己创建的决策单**不提供评议入口**（界面不显示评议按钮）；发起人“最终怎么选”由 §3.5 复盘单独记录，不混入众议票数。
- **可见范围三档（创建决策单时选定）**：
  - **仅自己（草稿）**：未发布，不产生评议。
  - **群内**：决策单发布到某个群组，**仅该群成员可浏览与评议**；非成员即使拿到链接也**不可见**。
  - **公开**：决策单进入**公开广场**，所有网友可浏览、可评议（受 §五 内容安全约束）。
- **群组**：用户**自行建群**，通过**邀请链接**邀请他人加入，点开链接并完成登录建档者即成为群成员（以 `openid` 记录）。**一张决策单只发布到一个群**。群只是**分组概念**：群有**名称与头像**（群主可修改）；群主可**解散**、可**移除成员**，成员可**退出**，退出/被移除/解散后已评议者仍可回看参与过的决策单（见下「内容可见性」）。**解散群时，该群「评议中」的决策单自动转为「已关闭」**（停止评议、不出报告，见 §3.4）。**邀请他人加入自己的群即属拉新**：被邀请的新用户溯源记为邀请人（邀请人与邀请计数落库留痕）。群组**取代**原先“逐次转发微信好友/群”的临时分享模式——评议入口固定绑定到群，成员可控，决策单不会因二次转发扩散给非成员。
- **重复评议：一条有效 + 可修改**：同一 `openid` 对同一决策单只算**一条有效评议**。该评议在**冷静期截止前可反复修改**自己的倾向（所选备选项）与观点文字，但始终只计入一条；**冷静期一旦截止，不可再修改**。
- **发起人对他人评议的处置**：发起人可**关闭评议**（转「已关闭」，停止评议且**不出报告**）、可**删除自己的决策单**（连带全部评议）；**不能改写他人评议文字**。**公开档**的评议人/网友可**举报**触发平台审核——举报**仅限公开档**（公开广场属 UGC，群内档由发起人关闭评议或删除决策单自行处置），因引入公开广场，**举报 / 内容审核从二期提前至 MVP 上线必做**（见 §五、§七）。MVP **不设运营后台**：举报落库留痕、处置延后二期；微信审核返回「需人工复审」时自动按「不通过」退回处理（无人工复审）。
- **内容可见性**：群内与仅自己档决策单**不出现在任何公开列表**；群内档仅群成员可达，**已提交评议的评议人即使退群 / 群解散仍可回看**该决策单与自己参与的评议（评议人都可见）；公开档进入公开广场供陌生人浏览，全量过内容安全接口。

### 3.2 「强制填写评议观点」——机制的灵魂，也是最容易劝退评议人的地方
规则：只投票不写字，**提交不了**。但需求要把摩擦设计得「有引导、可承受」：

- 评议观点**不能为空**（只挡纯投票空文，不设最低字数门槛）。
- 提供**结构化引导**而非空白框：把输入提示拆成「从思危/思退/思变角度说说你的看法」，降低「不知道写啥」的心理门槛。

> 需求取舍：宁可能要多一步输入，也不要有「投了 A 但什么都不说」的无效数据。

### 3.3 冷静期——「强制等待」的价值与反人性之间的平衡
冷静期是差异化机制，纯强制等待会与用户「现在就想要答案」的诉求冲突。确定规则如下：

- **冷静期内**：持续接收评议，但**对发起人不展示倾向汇总**（不看各选项票数，只看一条条单点观点，避免提前被票数带节奏）。
- **评议人之间「相互可见 + 先评后看」**：评议人须先提交本人评议，方可查看其他评议人的观点与各自倾向；展示内容为单条观点文字，**不提供实时各选项票数汇总**（与上条对发起人隐藏汇总的逻辑一致，共同防止从众带节奏）；评议人之间**只读不可互相回复**，追评/盖楼随二期讨论能力一并再做。**未参与评议者不可查看他人评议内容**——满员后未提交评议的人同样不可见（先评后看始终以已提交评议为前提）。
- **冷静期截止**：自动生成决策报告（各选项人数汇总，**报告仅发起人可见**）；截止后评议锁定，不再接收新评议、评议人也不可再改（见 3.1）。
- **允许提前结束**：发起人可在冷静期未满时主动结束评议、立即出报告（区别于「关闭评议」：关闭同样停止评议但**不出报告**、进入「已关闭」态，见 §3.4）。系统对该决策单**打「未满冷静期」标记**，复盘时（§3.5）并列展示，用于对照「冲动提前 vs 充分等待」的结果差异——这正是复盘功能的洞察点，而非单纯放行。
- **到期提醒用订阅消息**：冷静期结束是异步的、发生在用户离开小程序之后，必须提醒否则报告生成了没人看。确定用**微信一次性订阅消息**在截止时提醒发起人；订阅授权在**创建决策单时一次性发起**（此时用户动机最强、最愿意授权）。发起人**拒绝订阅授权时，到期不发送任何提醒**（无站内降级）。

### 3.4 决策单的生命周期状态（需求视角，非数据库）
一个决策单在需求上必然经历这些状态，所有功能都挂在这条主线上：

```
草稿 → 评议中(冷静期倒计时) → 已截止(报告生成) → 已复盘(回填结局)
                ├─ 发起人提前结束 → 立即出报告（打「未满冷静期」标记）
                └─ 发起人关闭评议 → 已关闭（停止评议、不出报告）
```

- **草稿**：填了决策内容但**尚未对外生效**，不产生评议。公开档提交后进入「待审核」子态（对外不可见）；审核不过退回本子态、**允许发起人就地编辑 title、content、options、图片与标签**后重提（**不限次数**）。
- **评议中**：决策单**已对外生效**——群内档提交即进本态；公开档须**审核通过**才进。本态下可被评议、结果对发起人部分隐藏（见 3.3）。**一旦进入本态，title、content、options、图片与标签均锁定**；要修改必须走「关闭评议 → 重建新决策单」流程，避免评议基础漂移。
- **已截止**：冷静期到 / 提前结束，报告生成，各选项结果对发起人可见（报告仅发起人可见）。
- **已关闭**：发起人主动**关闭评议**——停止接收评议、**不生成报告**；旧单保留归档，要改内容需重建新决策单。
- **已复盘**：发起人回填「我最终选了什么 + 实际发生了什么」，形成档案闭环。

> 「已复盘」是产品独有的沉淀价值，也是留存钩子——用户会想回看自己过去的决策准不准。

### 3.5 决策复盘——把「当初建议」和「真实结局」做对照
需求要点（不只是让用户填个结果）：

- 复盘时**并列展示**：当初各评议人的倾向与观点摘要 + 发起人最终选择 + 实际结局。
- 目的：让用户直观看到「听谁的对了 / 当初忽略了哪个风险」。这是把一次性工具变成「个人决策成长档案」的关键。
- 复盘是**可选**动作，不强制（否则增加流失）；但通过「已截止」状态提醒来引导。

### 3.6 零评议兜底——没人评时由 AI 补一份三思参考
为避免「发出去无人评议 → 空报告静默死亡」这一冷启动死局：
- **触发**：决策单到冷静期截止时，若**有效评议为 0 条**，自动生成一份 **AI 三思参考**（按思危/思退/思变给出分析 + 各选项权衡），替代空报告。
- **定位**：AI 内容**仅作参考**，与真人评议同等挂「仅供参考，决定权在你」声明。兜底仅在冷静期截止时零评议触发，截止后评议已锁定，不存在真人评议晚于 AI 生成的场景。
- **与二期边界**：MVP 仅做此「零评议兜底」最小用例；完整的「提交即 AI 预三思」仍留二期（见 §七）。

## 四、功能需求拆解（按模块，聚焦「要做什么」）

### 4.1 创建决策单
- 必填：**标题**（一句话概括本次决策，≤30 字）、内容（自由描述两难处境、背景与纠结点）、备选方案（**≥2 个，发起人自定义、不限两个**）、冷静期时长、**可见范围**、**评议人数上限**。（不再要求发起人分段填写思危/思退/思变，三思改由评议与报告承载。）
- 冷静期时长档位：MVP 默认提供 **12 小时 / 24 小时 / 3 天 / 7 天** 四档供选择；具体数值留待实现阶段按需微调（不影响数据结构）。
- 评议人数上限：创建时必填，**最少 1 人**；群内档**最多不超过当前群成员数**，公开档**最多 100 人**。评议人数达到上限后**不再接收新评议**（已提交的评议在冷静期内仍可修改，见 §3.1）。
- 可选上传图片：决策单可附图片，**最多 3 张**；公开档图片须过图片审核（见 §五.3）。
- 可选标签（**仅公开档**）：多选，**最多 5 个**；标签由平台预置（类似「圈子」的归类概念），公开档在广场可按标签筛选。群内/仅自己档不提供标签选择。
- 可见范围（三档，见 §3.1）：**仅自己（草稿）/ 群内 / 公开**。选「群内」需指定目标群组（**任意自己所在的群——群内任何成员均可发布决策单到该群，不限群主**），可现场新建群并生成邀请链接（邀请他人点开加入，**群邀请即拉新**，见 §3.1）；一张决策单只发布到一个群。选「公开」则进入公开广场供所有网友浏览、评议（受 §五 内容安全约束）。
- **发布流程与生效锁定**：群内档提交即生效进入「评议中」；公开档走「提交→待审核→通过才进广场、开始接收评议；不通过退回草稿、允许就地编辑重提（**不限次数**）」。一旦发布生效，title、content、options、图片与标签均**锁定**，要改只能「关闭评议 → 重建新决策单」（见 §3.4）。
- 隐私提示：表单页显著提示「不要填写身份证、手机号等隐私信息」；强隐私场景引导选「群内」。
- 产出：按可见范围发布到所选群或公开广场；群组的邀请通过微信分享**邀请链接/卡片**完成（取代原先逐次把决策单转发给微信好友的临时分享模式）。

### 4.2 评议（群成员 / 公开网友）
- 查看决策单全文 → 已登录且已填写昵称头像（见 3.1）→ 点击所选**选项按钮** → 弹出观点填写弹窗（所选倾向已带出 + 写观点，观点不能为空，见 3.2）→ 提交。
- 身份统一为「评议人」，界面不出现判官/通过/驳回。
- 以 `openid` 记录评议人身份（昵称/头像），供复盘对照；同一人只算一条有效评议。
- **满员提示**：评议人数达上限后，评议入口显示「评议已满」，不再接收新评议（见 §4.1）。
- 评议人视角（先评后看，见 3.3）：提交本人评议后即可查看他人观点与各自倾向，仅展示单条观点、不提供实时各选项票数汇总，他人评议只读不可回复。
- **回看与失效展示**：①冷静期截止后，评议人**仍可回看**决策单全文与自己当初那条评议（本人评议截止后不可改，见 3.1），但不再接收新评议；报告（各选项人数汇总）**仅发起人可见**；②发起人删除决策单后，任何旧链接 / 群入口再次进入均显示友好提示页「该决策单已被发起人删除或不存在」，不报错、不白屏。

### 4.3 冷静期与结果汇总
- 期内：接收评议，发起人不看汇总。
- 截止：自动汇总各选项人数，生成【众三思决策报告】，**仅发起人可见**。
- 报告固定声明：「仅供参考，不代表最终建议，决定权在你」。

### 4.4 个人中心
- 进入小程序即**静默登录**（`wx.login` 换取 `openid` 建档，用户无感、无授权弹窗）；昵称/头像在需要时引导用户主动填写（微信头像昵称填写能力）。
- 我的页面展示用户**头像、昵称**与**加入时间**（首次登录建档时间，见 §3.1）。
- **个人信息编辑页**：头像（微信头像选择能力 + 预设头像兜底）、昵称（微信昵称填写能力）、性别（手动选择，微信授权已不返回性别）；保存即覆盖更新。
- 我的页面提供**统计区**：我发起的决策单数、我参与评议的次数、我的决策单累计收获的评议数（均实时统计，不冗余存储）。
- 我的决策单（决策单列表入口）：按生命周期状态归类（进行中 / 已结束归档），并提供「我评议过的」视图（回看自己参与评议的决策单——退群/被移除/群解散后仍可由此回看）。
- 我的页面提供**客服入口**（微信客服会话）与**「关于」弹窗**（产品版本、免责声明、隐私政策）。
- 决策复盘：见 3.5。
- 历史归档：可随时回看，形成个人决策档案。

### 4.5 群管理
- 我的群：群列表（群头像、群名、成员数），点击进入群详情；可建群、生成邀请链接邀请他人加入（群邀请即拉新，见 §3.1）。
- 群详情：展示群信息（名称、头像、成员数）；群主可**修改群名称/群头像**、**邀请入群**；下方展示该群「评议中」的决策单列表，并提供群决策单列表入口（可按状态筛选：评议中/已截止/已关闭/已复盘）。
- 成员列表：展示群成员；群主可**移除成员**（被移除者同退群处理，其已评议的决策单仍可回看）。
- 群成员可**退出**群；群主可**解散**群（解散时该群「评议中」的决策单自动转「已关闭」，见 §3.1）；退出/解散入口在群详情页与成员列表页均提供。
- 群只是分组概念，不承载群内聊天、公告等强管理能力（二期见 §七.3）。

### 4.6 公开广场浏览
- 广场为**最新公开决策单列表**（仅审核通过的公开档单，按发布时间倒序），**默认展示最新 50 个**，上拉继续加载更多。
- 列表点击决策单 → **弹窗查看详情**（不跳页）。
- 页面提供**「随机查看」入口**：随机抽一个**未结束（评议中）**的公开决策单，弹窗展示；弹窗内**左右滑动切换**下一个随机单（底部「换下一个」按钮同步提供）。
- 弹窗展示完整详情：内容/图片/标签、发起人、评议进度、观点区（先评后看）与评议区（选项按钮 + 弹出观点填写弹窗提交，观点不能为空，见 §3.2、§4.2）——**弹窗内可直接评议，无需跳页**；发起人的管理操作（提前结束/关闭/删除）仍在详情页（§4.2）。
- 广场页与首页一样提供**「发起决策」悬浮按钮**入口，点击跳创建决策单（§4.1）。

## 五、文案与合规需求（不可妥协项）

这是把「评审友好度 / 上架通过率」当成需求来做，而非事后补救：

1. **词汇红线**：全端禁用「判官、申请、驳回、通过」；统一「决策单、评议人、倾向某选项」。
2. **去责任化**：每个可能产生「建议感」的位置（报告、评议、结果页、AI 兜底）反复声明「建议仅供参考，最终决定权归你」。
3. **公开档内容安全（仅公开档必做）**：**只有「公开」档**决策单及其全部评议，发布前后须经微信内容安全接口过滤（文本用 `msgSecCheck`，决策单图片用 `mediaCheck` 审核，MVP 支持每单最多 3 张图片）；**公开档内容提交后先进入「待审核」（对外不可见），审核通过才进公开广场、开始接收评议；不通过则退回草稿可编辑态，发起人就地改 content、options、图片与标签后重提（不限次数）**（「待审核/通过/不通过」的当前闸门态与逐次审核明细分开记录：当前态控制对外可见，明细留痕供审计）；并提供**举报**能力、制定社区规则（禁止嘲讽、人身攻击、涉黄涉政）。MVP 无运营后台，**举报仅落库留痕、处置延后二期**（§七.4）；「需人工复审」自动按不通过处理。**「群内」与「仅自己」档属私密分享，不做平台内容审核**，由发起人自行关闭评议或删除决策单处置。
   > ⚠️ 合规提示：群内仍是多人可见的 UGC，平台负内容安全责任；此处按决策暂免群内审核，但建议保留 `msgSecCheck` 调用能力（默认关闭），一旦政策/风险需要可对群内一键开启，无需改结构。
4. **隐私防呆**：在**决策内容输入框、决策单对外发布（入群 / 公开）前**这两处涉及敏感内容输入/外发的功能位置，均提示不填身份证、手机号等敏感信息；强隐私场景（如感情抉择）引导选用「群内」而非「公开」。
5. **视觉气质**：**B+微国风**——现代极简为骨（白底灰阶 + 双档蓝：操作主蓝 #4E75C9 / 品牌深蓝 #3B5BA5），国风只进品牌层与语义点缀（宋体标题、印章红状态徽章），不复刻对标产品样式（避免换皮观感）。具体规范见页面设计方案 §1.4。

## 六、成功指标（MVP 上线后如何判断「做成了」）

需求不仅要定义做什么，还要定义「怎么算有效」：

- **发布率**：创建决策单后，实际发布出去（入群或公开）的比例（验证「愿意把决策交出去评议」这一核心假设）。
- **评议转化率**：一份决策单平均收到多少条**带文字**的有效评议（验证 3.2 的强制机制是否可行、评议人是否买账）。
- **冷静期完成率**：到期后发起人回来看报告的比例（验证 3.3 提醒机制的必要性）。
- **复盘回填率**：结束后真的回来填结局的比例（验证「决策档案」这一差异化价值是否成立）。

> 前两项是 MVP 生死线：如果用户不愿发布、评议人不愿写评议，机制就跑不起来，后续 AI 深化都无从谈起。

> 小程序名称【众三思】**已确认可注册**。

## 七、二期演进方向（MVP 明确不做，仅列需求锚点）

> 注：原列于二期的「公开广场 + 内容审核 + 举报」已因产品决策**提前纳入 MVP**（见 §3.1、§五）。本节仅保留仍在二期的事项。

1. **AI 预三思（完整版）**：提交即由 AI 先给出思危/思退/思变参考再交人评议；MVP 仅实现「零评议兜底」最小用例（见 §3.6）。
2. **个人决策统计**：跨决策单的复盘数据沉淀（我历史上听谁的更准 / 哪类决策容易冲动）。
3. **群管理增强**：多群、群成员管理、@提醒、群内决策单归档检索等（MVP 仅做基础自建 + 邀请加入 + 解散/退出；群邀请拉新已含 MVP）。
4. **运营后台**：标签维护（MVP 用预置种子数据）、举报处理（MVP 仅落库留痕）、审核人工复审（MVP 期间「需人工复审」自动按不通过处置）。
