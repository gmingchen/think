# 小程序基础数据表设计模板（建表脚本）

> 通用、可跨小程序项目复用的基础表模板：基础字段约定 + 用户表 + 登录流水表 + 订阅消息相关三表。
> 只含与业务无关的通用结构，具体业务表请另建文档，勿混入本模板。

## 通用约定

- 数据库：MySQL 8.0，引擎 InnoDB，字符集 `utf8mb4` / `utf8mb4_0900_ai_ci`。
- 每张表统一包含基础字段：`id`、`created_at`、`updated_at`、`deleted_at`、`deleted`。
- 外键为逻辑外键（不建物理 FOREIGN KEY），配合普通索引。
- 软删除：`deleted`（0-未删除 1-已删除）+ `deleted_at`（删除时间，未删除为 NULL）。

## 1. 用户表 `user`

> 以微信 `openid` 记录用户身份，供展示与关联查询；非独立注册账号体系。

```sql
CREATE TABLE `user` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `openid`         VARCHAR(64)  NOT NULL COMMENT '微信openid',
  `unionid`        VARCHAR(64)  DEFAULT NULL COMMENT '微信unionid',
  `nickname`       VARCHAR(50)  NOT NULL DEFAULT '' COMMENT '昵称',
  `avatar`         VARCHAR(255) NOT NULL DEFAULT '' COMMENT '头像（预设标识）',
  `sex`            TINYINT      NOT NULL DEFAULT 2 COMMENT '性别：0-女 1-男 2-未知',
  `inviter_id`     BIGINT UNSIGNED DEFAULT NULL COMMENT '邀请人用户ID',
  `invite_count`   INT          NOT NULL DEFAULT 0 COMMENT '邀请用户数',
  `status`         TINYINT      NOT NULL DEFAULT 1 COMMENT '状态：0-禁用 1-启用',
  `created_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`     DATETIME     DEFAULT NULL COMMENT '删除时间',
  `deleted`        TINYINT      NOT NULL DEFAULT 0 COMMENT '是否删除：0-未删除 1-已删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`),
  KEY `idx_inviter` (`inviter_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户表';
```

> 注：`sex` 因微信 `getUserProfile` 改版，实际多返回默认「2-未知」，字段保留但不预期有有效数据。

## 2. 用户登录流水表 `user_login_log`

> **只增不改（append-only）** 的登录事件流水，用于登录留痕与日活（DAU）统计。

```sql
CREATE TABLE `user_login_log` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '登录日志ID',
  `user_id`     BIGINT UNSIGNED NOT NULL COMMENT '登录用户ID',
  `openid`      VARCHAR(64) NOT NULL COMMENT '微信openid',
  `created_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '登录时间',
  `updated_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`  DATETIME    DEFAULT NULL COMMENT '删除时间',
  `deleted`     TINYINT     NOT NULL DEFAULT 0 COMMENT '是否删除：0-未删除 1-已删除',
  PRIMARY KEY (`id`),
  KEY `idx_user` (`user_id`),
  KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='用户登录流水表（只增不改，DAU 统计源）';
```

> 说明：每次登录授权追加一行，不做 UPDATE；DAU 按 `created_at` 日期聚合 `DISTINCT user_id`。表体随时间增长，数据量大时可按月归档/分区。

## 3. 订阅消息模板配置表 `subscribe_template`

> 配置各类通知对应的微信订阅消息模板 ID；`type` 由业务自定义并保证唯一。

```sql
CREATE TABLE `subscribe_template` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `type`        VARCHAR(30) NOT NULL COMMENT '通知类型标识（业务自定义，唯一）',
  `template_id` VARCHAR(50) NOT NULL COMMENT '微信模板ID',
  `remark`      VARCHAR(100) DEFAULT NULL COMMENT '备注',
  `created_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`  DATETIME    DEFAULT NULL COMMENT '删除时间',
  `deleted`     TINYINT     NOT NULL DEFAULT 0 COMMENT '是否删除：0-未删除 1-已删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='订阅消息模板配置表';
```

## 4. 用户订阅额度记录表 `subscribe`

> 记录每个用户对某模板累计的「可发送额度」（一次性订阅：每次授权累计 +1，发送后 -1）。

```sql
CREATE TABLE `subscribe` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `user_id`         BIGINT UNSIGNED NOT NULL COMMENT '订阅用户ID',
  `template_id`     VARCHAR(50) NOT NULL COMMENT '微信模板ID',
  `remaining_count` INT NOT NULL DEFAULT 0 COMMENT '剩余可发次数',
  `created_at`      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`      DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`      DATETIME    DEFAULT NULL COMMENT '删除时间',
  `deleted`         TINYINT     NOT NULL DEFAULT 0 COMMENT '是否删除：0-未删除 1-已删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_template` (`user_id`, `template_id`),
  KEY `idx_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='订阅消息记录表';
```

## 5. 订阅消息发送日志表 `subscribe_log`

> 每次调用微信订阅消息接口发送的记录与结果，便于排查失败与重试。

```sql
CREATE TABLE `subscribe_log` (
  `id`          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `user_id`     BIGINT UNSIGNED NOT NULL COMMENT '接收人用户ID',
  `template_id` VARCHAR(50) NOT NULL COMMENT '微信模板ID',
  `type`        VARCHAR(30) NOT NULL COMMENT '通知类型标识（业务自定义）',
  `biz_type`    VARCHAR(30) NOT NULL DEFAULT '' COMMENT '业务对象类型（业务自定义；无对象关联时留空）',
  `biz_id`      BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '业务对象 ID（无对象关联时置 0）',
  `status`      TINYINT NOT NULL COMMENT '发送状态：1-成功 2-失败',
  `message`     VARCHAR(500) DEFAULT NULL COMMENT '失败原因',
  `created_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at`  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted_at`  DATETIME    DEFAULT NULL COMMENT '删除时间',
  `deleted`     TINYINT     NOT NULL DEFAULT 0 COMMENT '是否删除：0-未删除 1-已删除',
  PRIMARY KEY (`id`),
  KEY `idx_user` (`user_id`),
  KEY `idx_type` (`type`),
  KEY `idx_biz` (`biz_type`, `biz_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci COMMENT='订阅消息发送日志表';
```

> 说明：`subscribe_log` 已预置多态字段 `biz_type` / `biz_id`，通知需关联具体业务对象时由调用方填入（例：某项目 = `DECISION` + `decision.id`）；无对象关联的纯通知（如活动公告）保持默认 `''` / `0` 即可，不影响主流程。`idx_biz` 支持日后按业务对象反查发送记录。
