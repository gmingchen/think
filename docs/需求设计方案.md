# 众三思 · 需求设计方案（MVP）

> 本文只讨论「需求」本身：要解决什么问题、给谁用、怎么算做成了、有哪些必须拍板的业务规则。
> 不涉及数据库设计、页面拆分、接口与技术选型。产品定位与功能清单见 `../index.md`，本文是其需求侧的深化与补强。

---

## 一、需求本质：我们到底在解决什么

两难决策的真实痛点，不是「缺一个建议」，而是三个更底层的东西：

1. **当事人身在局中，视角受限**——只盯着一时的收益或恐惧，看不清风险、退路和长期改变。
2. **冲动窗口**——很多两难（裸辞、大额消费、表白、分手）是在情绪峰值时做的决定，缺一个「强制等一下」的机制。
3. **建议散落在微信聊天记录里**——朋友口头说了两句就过去了，没有结构化、无法沉淀、事后无法复盘「当初谁说了什么、结果如何」。

所以众三思的核心价值不是「帮你做决定」，而是：

> **把一次两难决策，变成一份结构化的、有旁观者参与的、可事后复盘的个人决策档案。**

对应产品三根支柱：**结构化（三思框架）+ 众议（好友评议）+ 时间（冷静期与复盘）**。

---

## 二、目标用户与关键场景

### 2.1 目标用户
- **发起人**：正面临一个具体的、难以自行拍板的人生两难。情绪上「想听别人的看法，但又怕被别人替自己做决定」。
- **评议人**：发起人的微信好友/群成员，愿意帮忙但又缺乏上下文，需要被引导才能给出有价值的意见。

两类人是同一个人不同时刻的身份，产品必须让「当评议人」这件低成本的事也顺畅，否则发起人转发出去没人评，机制就空转。

### 2.2 典型场景（需求优先级按此排）
| 场景 | 说明 | MVP 是否覆盖 |
| --- | --- | --- |
| 要不要裸辞 / 换 offer | 高风险、长冷静期、需要旁观者补盲 | ✅ 核心 |
| 要不要买大额消费品（相机、车） | 冲动型，冷静期价值最大 | ✅ 核心（对标差异场景） |
| 感情抉择（表白 / 复合 / 异地） | 强隐私，只信好友 | ✅ 核心（好友私域正好匹配） |
| 学业 / 考研 / 留学 | 多方权衡 | ✅ 核心 |
| 养宠物 / 搬家 / 借钱给人 | 长尾两难 | ✅ 通用表单可承载 |

## 三、核心业务规则（已定稿）

> 这几条是需求能否成立的关键。以下均为确定的落地规则，不再保留待定项。

### 3.1 「好友评议」的授权、身份与权限边界
MVP 不做好友关系绑定、不做通讯录同步，确定规则如下：

- **进入即评议，但必须先授权**：任何人点开分享卡片都能进入浏览，但**提交评议前必须完成微信授权**，拿到 `openid` + 昵称 + 头像。以 `openid` 作为评议人唯一身份，不建独立账号体系。授权的唯一必要用途是区分「谁评的」，支撑 §3.5 复盘时的「当初谁建议、我最终怎么选」对照。
- **重复评议：一条有效 + 可修改**：同一 `openid` 对同一决策单只算**一条有效评议**。该评议在**冷静期截止前可反复修改**自己的倾向（A/B）与观点文字，但始终只计入一条、不新增计数；**冷静期一旦截止，评议人不可再修改**自己已提交的评议。
- **发起人对他人评议不可删改**：发起人可以**关闭评议**（决策单转「已截止」）、可以**删除自己的决策单**（连带全部评议一并删除）；但**不能删除或修改任何单条他人评议**，避免「只留好评」破坏评议机制。他人评议的举报 / 隐藏能力，随二期公域广场配套的内容审核一并再做。
- **内容可见性**：决策单及其评议**仅通过分享路径可达**，全端无任何公开列表页 / 陌生人可浏览入口，从结构上规避公域抓取与内容风险。

### 3.2 「强制填写评议观点」——机制的灵魂，也是最容易劝退评议人的地方
规则：只投票不写字，**提交不了**。但需求要把摩擦设计得「有引导、可承受」：

- 设**最低字数门槛**（推荐 ≥ 15 字，既挡灌水又不强求小作文）。
- 提供**结构化引导**而非空白框：把输入提示拆成「从思危/思退/思变角度说说你的看法」，降低「不知道写啥」的心理门槛。
- 可选**快捷视角标签**（如「我更看重风险」「我建议先留退路」），点了自动带出一句引导语，用户再补自己的话——既保证有真实文字，又降低启动成本。

> 需求取舍：宁可能要一点评议门槛，也不要有大量「投了 A 但什么都不说」的无效数据。

### 3.3 冷静期——「强制等待」的价值与反人性之间的平衡
冷静期是差异化机制，纯强制等待会与用户「现在就想要答案」的诉求冲突。确定规则如下：

- **冷静期内**：持续接收评议，但**对发起人不展示倾向汇总**（不看 A/B 票数，只看一条条单点观点，避免提前被票数带节奏）。
- **冷静期截止**：自动生成决策报告（A/B 人数 + 精选观点）；截止后评议锁定，不再接收新评议、评议人也不可再改（见 3.1）。
- **允许提前结束**：发起人可在冷静期未满时主动结束评议、立即出报告。系统对该决策单**打「未满冷静期」标记**，复盘时（§3.5）并列展示，用于对照「冲动提前 vs 充分等待」的结果差异——这正是复盘功能的洞察点，而非单纯放行。
- **到期提醒用订阅消息**：冷静期结束是异步的、发生在用户离开小程序之后，必须提醒否则报告生成了没人看。确定用**微信一次性订阅消息**在截止时提醒发起人；订阅授权在**创建决策单时一次性发起**（此时用户动机最强、最愿意授权）。

### 3.4 决策单的生命周期状态（需求视角，非数据库）
一个决策单在需求上必然经历这些状态，所有功能都挂在这条主线上：

```
草稿 → 评议中(冷静期倒计时) → 已截止(报告生成) → 已复盘(回填结局)
                ↑ 随时可被发起人关闭
```

- **草稿**：填了三思但未分享出去，不产生评议。
- **评议中**：已分享、可被评议、结果对发起人部分隐藏（见 3.3）。
- **已截止**：冷静期到 / 提前结束，报告生成，A/B 结果公开给发起人。
- **已复盘**：发起人回填「我最终选了什么 + 实际发生了什么」，形成档案闭环。

> 「已复盘」是产品独有的沉淀价值，也是留存钩子——用户会想回看自己过去的决策准不准。

### 3.5 决策复盘——把「当初建议」和「真实结局」做对照
需求要点（不只是让用户填个结果）：

- 复盘时**并列展示**：当初各评议人的倾向与观点摘要 + 发起人最终选择 + 实际结局。
- 目的：让用户直观看到「听谁的对了 / 当初忽略了哪个风险」。这是把一次性工具变成「个人决策成长档案」的关键。
- 复盘是**可选**动作，不强制（否则增加流失）；但通过「已截止」状态提醒来引导。

## 四、功能需求拆解（按模块，聚焦「要做什么」）

### 4.1 创建决策单
- 必填：标题、方案A、方案B、思危、思退、思变、冷静期时长。
- 评议模式：MVP 仅「好友评议」。
- 场景模板：MVP **确定上线 4 个**高频场景——大额消费 / offer 求职 / 情感抉择 / 学业抉择。模板本质是**预填充三思提示语**，降低「不知从何写起」的启动成本，不改变数据结构；不为凑数新增低频模板。
- 隐私提示：表单页显著提示「不要填写身份证、手机号等隐私信息」。
- 产出：生成可转发微信好友/群的**分享卡片**。

### 4.2 好友评议
- 查看决策单全文 → 完成微信授权（见 3.1）→ 选倾向（A/B）→ 写观点（强制，见 3.2）→ 提交。
- 身份统一为「评议人」，界面不出现判官/通过/驳回。
- 以 `openid` 记录评议人身份（昵称/头像），供复盘对照；同一人只算一条有效评议。

### 4.3 冷静期与结果汇总
- 期内：接收评议，发起人不看汇总。
- 截止：自动汇总 A/B 人数、精选/高赞观点，生成【众三思决策报告】。
- 报告固定声明：「仅供参考，不代表最终建议，决定权在你」。

### 4.4 个人中心
- 我的决策单：按生命周期状态归类（进行中 / 已结束归档）。
- 决策复盘：见 3.5。
- 历史归档：可随时回看，形成个人决策档案。

## 五、文案与合规需求（不可妥协项）

这是把「评审友好度 / 上架通过率」当成需求来做，而非事后补救：

1. **词汇红线**：全端禁用「判官、申请、驳回、通过」；统一「决策单、评议人、倾向方案A/倾向方案B」。
2. **去责任化**：每个可能产生「建议感」的位置（报告、评议、结果页）反复声明「建议仅供参考，最终决定权归你」。
3. **私域优先**：MVP **坚决不做陌生人公域广场**，从源头规避 UGC 大规模内容审核与下架风险。
4. **隐私防呆**：在**三思输入框、分享卡片生成前**这两处涉及敏感内容输入/外发的功能位置，均提示不填身份证、手机号等敏感信息。
5. **视觉气质**：简约偏国风，贴合「三思」调性，不复刻对标产品样式（避免换皮观感）。

## 六、成功指标（MVP 上线后如何判断「做成了」）

需求不仅要定义做什么，还要定义「怎么算有效」：

- **分享率**：创建决策单后，实际转发出去的比例（验证「愿意把决策发给好友」这一核心假设）。
- **评议转化率**：一份决策单平均收到多少条**带文字**的有效评议（验证 3.2 的强制机制是否可行、评议人是否买账）。
- **冷静期完成率**：到期后发起人回来看报告的比例（验证 3.3 提醒机制的必要性）。
- **复盘回填率**：结束后真的回来填结局的比例（验证「决策档案」这一差异化价值是否成立）。

> 前两项是 MVP 生死线：如果用户不愿转发、好友不愿写评议，机制就跑不起来，后续公域/AI 都无从谈起。

## 七、二期演进方向（MVP 明确不做，仅列需求锚点）

1. 可选**公开广场**（陌生人评议）+ 内容安全审核接口 + 社区规则（禁止嘲讽/人身攻击）。
2. **AI 预三思**：提交后 AI 先给出思危/思退/思变参考，再交人评议。
3. 评议**点赞与高赞排序**（增强优质观点的可见性）。
4. 他人评议的**举报 / 隐藏**能力（配合内容审核，见 3.1）。
5. **个人决策统计**：跨决策单的复盘数据沉淀（我历史上听谁的更准 / 哪类决策容易冲动）。
